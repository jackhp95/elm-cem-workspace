- a non-boolean reflected scalar the CEM links via `fieldName` → **property**.

**elm/html rationale (Jack asked "match elm/html"):** investigated elm/html 1.0.1 `Html.Attributes` — it is NOT a consistent rule. It defaults to property (65/85 setters: stringProperty/boolProperty) with 20 attribute exceptions that are a mix of principled (`list`/`form` = read-only/element DOM property; `height`/`width` = rendered-px≠specified; `draggable` = enumerated) and INCONSISTENT (`span`/`start` → property via `stringProperty ... String.fromInt`, but `cols`/`colspan`/`height`/`width`/`size`/`rows`/`min|maxlength` → attribute — same technique, opposite choice; plus camelCase attr-name sloppiness `attribute "tabIndex"`/`"minLength"`). DECISION (Jack approved): do NOT chase elm/html parity. elm/html targets NATIVE elements; we target WEB COMPONENTS + SSR, which observe/serialize ATTRIBUTES not properties (that's the NB2b bug). Our rule is cleaner + platform-correct: **controlled trio (value/checked/selected) → property** (the one place elm/html's property is load-bearing = controlled re-forcing), **everything else reflected → attribute**. So `value` stays property EVERYWHERE (the ProgressIndicator display-only refinement was explicitly rejected — match elm/html there).
