# elm-html-intermediate-representation

The phantom-typed HTML IR — the **Tier-0 substrate** every library in the elm-cem
ecosystem builds on. One opaque `Element accepts admittedBy msg`, shared by native
HTML (`TypedHtml`) and every generated design-system brand (`M3e`, …), so content
from any brand nests in any other without conversion, and both nesting directions
are compiler-checked.

This is the **only hand-rolled package** in the system. Everything delivered above
it is config-generated. The package name is deliberately verbose: this is
infrastructure for generators and library authors, not an application-facing API.

## Install

```
elm install jackhp95/elm-html-intermediate-representation
```

This package is a **substrate for brand authors and generator output**, not a
direct application dependency. Application code imports a brand package (e.g.
`jackhp95/elm-m3e`) which re-exports the element type; the IR is a transitive
dependency reached via that brand.

## Who uses this

The `elm-cem` generator emits generated brand packages (currently `TypedHtml` for native
HTML, `M3e` for Material 3) that **import** this package as an ordinary Elm dependency.
Neither brand copies or re-emits the IR; they depend on it like any other library and
build their types on top of it. This is the only hand-rolled package in the system —
everything above Tier 0 is config-generated.

Consumer breakdown:

- **elm-cem (generator)** — reads the IR's module signatures to produce honest phantom
  rows; RETIRED `injectRuntime` (verbatim runtime injection) in favour of this import.
- **TypedHtml** (native brand, config-generated from a hand-authored native manifest) —
  imports `HtmlIr.*` and mints `TypedHtml.*` modules on top.
- **M3e** (design-system brand, config-generated from the `@m3e/web` CEM) — same
  import relationship; `M3e.Button`, `M3e.Card`, … are thin layers on the IR.

## Quick start — building a minimal brand on top of the IR

A brand author (or generator) builds typed constructors by composing the IR levers.
Below is a self-contained illustration of the pattern; real brands are generated by
`elm-cem`, but this shows what the output looks like:

```elm
module MiniNative exposing (div, span, text)

import HtmlIr.Element exposing (Element)
import HtmlIr.Internal as I
import HtmlIr.Kind exposing (Supported)
import HtmlIr.Node as Node


-- Phantom row aliases for this brand's types
type alias DivAccepts =
    { flow : Supported }

type alias DivAdmittedBy =
    { flowCtx : Supported }


-- A typed div: accepts flow children, valid in flow contexts.
div :
    List (I.Attr { class : Supported } msg)
    -> List (Element DivAccepts DivAdmittedBy msg)
    -> Element DivAccepts DivAdmittedBy msg
div attrs children =
    I.fromNode
        (Node.node "div"
            attrs
            (List.map I.toNode children)
        )


-- A plain text atom: open accepts row, valid anywhere.
text : String -> Element {} {} msg
text s =
    I.fromNode (Node.text s)
```

Key points:

- `I.fromNode` is the **only way to mint an `Element`** — it lives in
  `HtmlIr.Internal` (the fenced forge, see below).
- Phantom rows are just extensible record type aliases; they are erased at runtime.
- `toNode` / `toHtml` are the render boundary; they discard rows.

## What it is

### Opaque types

| Type | Module | Role |
|---|---|---|
| `Element accepts admittedBy msg` | `HtmlIr.Element` | Two-row phantom element; the type every brand exposes |
| `Node msg` | `HtmlIr.Node` | Untyped structural tree beneath every element |
| `Attr capability msg` | `HtmlIr.Attribute` | Phantom-typed attribute / event / property — a **list** of facts, so it can be absent (`none`) or carry several |
| `Value tags` | `HtmlIr.Value` | Phantom-tagged enum token |
| `Supported` / `Shared` | `HtmlIr.Kind` | Cross-package phantom-row marker vocabulary |

All five are **opaque**: their constructors are only accessible via `HtmlIr.Internal`.

### The two-row `Element accepts admittedBy msg`

`accepts` (parent → child) records which slot kinds this element produces, or which
child kinds a slot demands. `admittedBy` (child → parent) records which parent
contexts this element is valid inside.

Composition unifies both edges: the child's `accepts` must be a subtype of the slot
demand, AND the container's context must appear in the child's `admittedBy`.

- **Producers** keep `accepts` open and `admittedBy` closed (specifying exactly
  which contexts they fit).
- **Containers** demand a closed `accepts` on children (specifying which child kinds
  they slot) and leave their own `admittedBy` polymorphic (layout code can nest
  anywhere).

Neither row is ever inspected at runtime; they are erased by the compiler.

### Module index

- **`HtmlIr.Element`** — the two-row phantom element.
  `accepts` (parent → child: which slot kinds it produces / a slot demands) and
  `admittedBy` (child → parent: which contexts it is valid inside). Producers keep
  `accepts` open and `admittedBy` closed; containers demand a closed `accepts` and
  inject an open demand for their own context. Both edges unify at composition.
- **`HtmlIr.Node`** — the untyped structural tree beneath every element
  (tag / text / fenced raw escape). `toHtml` is the render boundary.
- **`HtmlIr.Attribute`** — attributes with one open-producer/closed-consumer
  `capability` row (this is also how events are gated: `onClick` is a capability).
- **`HtmlIr.Value`** — phantom-tagged enum tokens.
- **`HtmlIr.Kind`** — the only shared markers: `Supported` (capability/value
  fields) and `Shared` (cross-library atom kinds). **Everything else is
  per-brand**: each brand mints its own `Brand`, `Ctx` (and `Role`) marker types,
  which is what keeps two brands' rows from unifying by accident
  (`verify/bad/CtxSpoof.elm` proves it).
- **`HtmlIr.Internal`** — the curated forge. Read its module doc before anything
  else; the trust model lives there.

## General levers only — opinionated ops are compositions

The IR ships general levers; every opinionated operation a brand needs is a
composition of them, built above the IR by generated code:

| brand-level op | composition of IR levers |
|---|---|
| element constructor | `fromNode (node tag attrs (List.map toNode children))` + honest rows from config |
| shared text atom | `fromNode (text s)` at `{ s \| sharedText : Shared }` |
| typed attr / event setter | `attribute` / `property` / `on` + honest capability row |
| enum token | `token` + honest tag row |
| `slotAs` (named-slot placement, free output row) | `fromNode << addAttribute (attribute "slot" name) << toNode` |
| `recast` (brand crossing, free output row) | `fromNode << toNode` |
| `delegate` (event capability-forget escape) | `recast` |
| absent attribute (a `False` boolean setter) | `none` |
| merging inline styles | `styles [ ( prop, value ) ]` — declarations merge across setters |
| builder (`build` pipe) | brand-side record accumulation; single `node` at `toElement` |
| legacy `Html` embed (native brand's one loud escape) | `fromNode << fromHtml` |

All of these compile against the real IR in `verify/` — see `MiniNative.elm` /
`MiniM3e.elm`, which are hand-written stand-ins for generated brand code.

## Trust model (the honest version)

Cross-package forging is **lint-fenced, not compiler-sound**. `HtmlIr.Internal`
must be exposed so generated brand packages can build on the IR; once exposed,
any consumer can import it and mint arbitrary rows (`verify/src/AttackForge.elm`
compiles a raw-`<script>`-into-text-slot smuggle on purpose). The
`NoInternalImportOutsideAllowed` rule in `jackhp95/elm-review-cem` is
**load-bearing**. Never advertise "compiler-guaranteed" without that caveat.

Curation rules, frozen at 1.0: functions and opaque types only; no data
constructors; no userland raw; no opinionated operations.

## Authoring-guide wrinkles (carry into brand docs)

- **Closed-row annotation asymmetry.** Enforcement requires a producer's
  `admittedBy` row to be closed, and a closed row cannot be annotated with a bare
  type variable. Inference sidesteps it (unannotated bindings compile); when an
  annotation is written, use the element's `<El>AdmittedBy` alias. Structural
  containers leave their own `admittedBy` polymorphic so layout code never hits
  this.
- **Alias both rows** (`<El>Accepts` + `<El>AdmittedBy`, shared `FlowCtx`-style
  context aliases) — mandatory for clean errors and docs.
- **R1**: all slot-mates of one container must share ONE closed
  `<Container>ChildAdmittedBy` alias (Elm lists are homogeneous).
- **R2**: a child whose valid-parent set diverges from its slot-mates gets a
  per-context helper variant (`source` vs `pictureSource`).
- **`map` is structural** (rows, tree shape, and rearrangeability preserved) —
  unlike the retired `markup-core` runtime, which rendered eagerly on map.
- **`addAttribute` on a text/raw leaf** promotes it to a `<span>` carrying the
  attribute — never silently dropped.

## Verify

```
./verify/run.sh
```

Compile-level oracle: 3 good cases must compile (cross-brand nesting /
zero-annotation inference / the honest forge attack), 7 bad cases must fail for
the documented reasons (option-in-div, wrong slot kind, enum misuse ×2, event on
non-interactive, cross-brand context spoof, forge-without-Internal). Error texts
land in `verify/out/`.
