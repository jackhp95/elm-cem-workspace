The "Html.Phantom / Html.Attributes.Phantom" refactor Jack refers to = **elm-cem#40** "elm-phantom re-layering + growth-stable packaging (design exploration)" (OPEN, `jackhp95/elm-cem`, status: proposal/not decided, 0 comments).

**Concept (matches Jack's verbal description):** reframe the shared runtime from "markup" to phantom-typed HTML — an IR superset of `elm/html`.
- `jackhp95/elm-phantom` exposes `Phantom.Html` / `Phantom.Html.Attributes` / `Phantom.Html.Events` (pure IR, no components). Naming rule: use `Phantom.Html.*`, do NOT squat `Html.*.Phantom`.
- Each Brand lib gets `Brand.Html.*` (raw), `Brand.Html.*.Phantom` (typed atoms), `Brand.ComponentName` (unified `.view`/`.build`/`.requires`), `Brand` (barrel).
- The a11y "markup" work becomes a **peer** generated lib on elm-phantom (today `markup-core` does double duty — runtime + lib; this separates them). Jack calls the rename target ~"elm-accessibility" = HTML-Phantom over built-in elements via a hand-authored pseudo-CEM (just attrs+events for built-in, non-custom elements).
- Brand libs share elm-phantom's `Element` and compose — like `elm/svg`+`elm/html` sharing `VirtualDom.Node`. Already how `Kind.Shared` works; rework just names it. CEM demotes to "just an input" (markup already generated from a hand-authored manifest).

**Type machinery ALREADY EXISTS** (markup's strict layer, shared `markup-core` runtime): `Element supported msg = El (Node msg)`, `Attr capability msg = Attr (() -> Html.Attribute msg)`, `Value tags` tokens, `Category.{Phrasing,Flow,…}`. Element↔attr validity (no `href` on `div`) and element↔child validity (direct children only) are ALREADY type-enforced via open-setter-row ⊆ closed-component-row unification. Element↔attr validity does NOT need attrs tagged by owning element — the closed component row does it; shared attrs (`disabled` on 53/130 m3e elements) stay ONE setter. So the reframe is mostly rename + re-org, not new type-safety design.

**⚠ The cited full design doc `planning/execution/2026-07-15-elm-phantom-relayering-design.md` was NEVER written** — dangling ref, absent from disk + every branch + the `planning-sync` mirror. #40's body IS the captured design. Reconstructing that doc is an obvious next step if this resumes.

**Real blocker surfaced by #40's pressure test (independent of the rename):** the 700 KB registry docs-cap cliff. elm-m3e standard facet already at 680k = **97% of cap** (build 80%); component-packing hits 99.7%. Size-greedy split → package cycles → unpublishable; topological cut → 0 cycles but `split.js` can't do topological packing today. Growth is the killer: +20% upstream @m3e/web growth → 18/123 components change package = 18 breaking module-moves (+50% → 49). **A growth-stable splitter (dependency-aware topological packing, pinned module→package + append-only, ~60-70% headroom budget) is REQUIRED REGARDLESS** of the naming decision — the current architecture is one upstream growth away from a forced breaking re-split.

**Also required:** finish CF-12 — 18 hardcoded `"Markup"` runtime assumptions in codegen must become a config field (runtime is no longer a Brand library). #39 (B1 markup-core Internal-exposure — cross-package forging stays compiler-unsound) is UNCHANGED by #40.

**Timing crux:** names + package topology freeze permanently at 1.0 (Elm/npm) → pre-1.0 is the ONLY non-breaking window for the reframe. Weigh vs pre-release rework risk.

**Open decisions (all deferred in #40):** adopt reframe pre-1.0 vs defer to breaking 2.0; component-cut vs layer-cut packaging; build the growth-stable splitter (required regardless); finish CF-12; final `Phantom.Html.*` prefix; fold in the markup 5→2 package collapse.
