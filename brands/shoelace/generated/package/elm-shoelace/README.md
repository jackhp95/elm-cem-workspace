# elm-shoelace

`jackhp95/elm-shoelace` — **type-safe Elm bindings for [Shoelace](https://shoelace.style/)
web components, the `Sl` brand.**

The whole of `src/` is generated by [`elm-cem`](../../../../../pipeline/elm-cem)
from Shoelace's own [Custom Elements Manifest](https://custom-elements-manifest.open-wc.org/)
(`@shoelace-style/shoelace`'s published `dist/custom-elements.json`) — every
module, its docs, and `exposed-modules` — so the library never drifts from the
upstream manifest. This is the workspace's second real brand (after `m3e` and
the native-HTML `html` brand), standing up the same pipeline against a
different, third-party component library.

> Publishing is human-gated. Until this package lands on the Elm registry,
> install it by source (add this package's `src/` plus the IR substrate's `src/`
> to your app's `source-directories`).

## Usage

The barrel module `Sl` is the canonical one-import surface:

```elm
import Sl
import Sl.Attributes
import Sl.Values

view =
    Sl.alert
        [ Sl.Attributes.variant Sl.Values.primary
        , Sl.Attributes.open True
        ]
        [ Sl.text "Your changes have been saved." ]
```

Per-component modules (`Sl.Button`, `Sl.Alert`, …) expose the same setters
namespaced; `elm-review` (see `review/`) migrates between the two forms with
`--fix`.

## Inputs & regeneration

The brand's only authored artifacts live in
[`brands/shoelace/inputs/cem/`](../../../inputs/cem):

- `custom-elements.json` — a vendored snapshot of Shoelace's published CEM
  (`@shoelace-style/shoelace@2.20.1`).
- `config/slots.json` — the tiny phantom config (`_brand: "Sl"`, the shared
  `text` atom). Shoelace needs none of M3E's opinion layers (examples, figma,
  MDN-native overrides).

```sh
pnpm --filter elm-shoelace run gen     # regenerate src/ from CEM + config
pnpm --filter elm-shoelace run check    # format + review + acid + validate + drift
```

`check:drift` enforces that the committed `src/` is byte-identical to a clean
regeneration — there are zero post-codegen hand tweaks.
