# Tangram Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the docs nav-rail's `menu`/`menu_open` toggle icon and the site favicon with a theme-aware two-triangle "tangram" mark, live-recoloring off `--md-sys-color-*` custom properties in-app and baked/port-updated for the favicon.

**Architecture:** New `docs/app/Logo.elm` builds the two-path SVG via `elm/svg` (a new dependency — not currently installed anywhere in this repo), wrapped into the typed `Element` world via `M3e.Unsafe.fromHtml`. The nav-rail toggle's existing `M3e.IconButton.selected`-slot swap mechanism (already tracks expand/collapse state) gets its two `M3e.icon [...]` children replaced with two calls into `Logo.elm` — no new Elm state. The favicon is regenerated by a new Node script using `@material/material-color-utilities` (already a transitive dependency of `@m3e/web` — confirmed installed) to bake the default theme's true resolved primary color, and the `setFaviconColor` port (declared in the theme-editor-drawer plan's Task 6, `docs/app/Theme/Ports.elm`) is wired to redo that same derivation client-side when the user changes seed color.

**Tech Stack:** Elm 0.19.1 + `elm/svg` (new dep), `@m3e/web`'s `--md-sys-color-*` custom properties, `@material/material-color-utilities` (HCT/tonal-palette color derivation — already installed transitively, confirmed at `node_modules/.pnpm/@material+material-color-utilities@0.4.0/`), `@resvg/resvg-js` (existing rasterizer, per Spec D's pinned-tooling decision), Node ESM (`docs/scripts/icons-gen/`).

**Depends on:** `docs/app/Theme/Ports.elm`'s `setFaviconColor` port — from `plans/2026-08-08-theme-editor-drawer.md` Task 6. Do Task 6 of that plan (or at minimum, declare the `setFaviconColor` port) before this plan's Task 6.

**Ground-truth corrections to the spec:**

- The spec describes the favicon convention as "plate/gradient wrapper kept per Spec D's existing convention: 46×46 rounded rect with a gradient." **This does not match the actual shipped `docs/public/favicon.svg` or the actual generator (`docs/scripts/icons-gen/brand-images.mjs`).** Read directly: the real favicon is a **bare glyph**, `viewBox="0 0 24 24"`, `fill="currentColor"` with a `<style>@media (prefers-color-scheme: dark){fill:#E6E0E9}</style>` override, no rounded-rect plate, no gradient, and **no `favicon.ico`** (the generator's own header comment explains why: "a raster has no CSS context to resolve `currentColor` against"). The gradient/plate treatment that IS in the generator (a `GRADIENT` constant) is used for `docs/public/og-card.png` (the 1200×630 social card), not the favicon. This plan follows the real current favicon convention (bare glyph, no plate) — see Task 6.
- The spec also implies the favicon's fill mechanism today is `currentColor`-based and asks this plan to change it to a **baked literal hex** (the default theme's resolved primary), which is a deliberate, correctly-described departure from today's `currentColor` convention — not a ground-truth error, just flagging that Task 6 is a real mechanism change, not a glyph-only swap.

- [ ] **Step 2: Write `Logo.elm`**

```elm
module Logo exposing (Colors, defaultColors, invertedColors, view)

{-| The tangram mark — two triangles, theme-aware via `--md-sys-color-*`
custom properties. Used as the docs nav-rail's toggle icon (`Shared.elm`)
and as the source-of-truth SVG geometry the favicon generator
(`docs/scripts/icons-gen/tangram-favicon.mjs`) mirrors — keep the two
`d` attribute path strings below in sync with that script's `PATHS`
constant if this geometry ever changes; they can't literally share code
across the Elm/Node boundary.

Not routed through `M3e.Icon`'s named-icon registry — that registry is
built for single-color icon-font-style glyphs, not two independently
fillable paths. Not a generalized `M3e.Logo` library component — this stays
docs-app-scoped per the spec's non-goal (revisit if a second consumer
wants it).
-}

import HtmlIr.Element exposing (Element)
import M3e.Unsafe
import Svg
import Svg.Attributes as SvgAttr


{-| The two triangles' fill colors — `small` is the smaller triangle (the
second `<path>`, which draws the notch), `big` is the larger one (the first
`<path>`, the full corner-to-corner triangle).
-}
type alias Colors =
    { small : String, big : String }


{-| Collapsed/closed nav-rail state, and the favicon's default: both
triangles the same brand-primary color — the plain mark.
-}
defaultColors : Colors
defaultColors =
    { small = "var(--md-sys-color-primary)", big = "var(--md-sys-color-primary)" }


{-| Expanded/open nav-rail state: small triangle inverts to
`inverse-surface`, big triangle to `inverse-primary`, accenting the
"this closes it" affordance.
-}
invertedColors : Colors
invertedColors =
    { small = "var(--md-sys-color-inverse-surface)", big = "var(--md-sys-color-inverse-primary)" }


{-| `Element accepts admittedBy msg` via `M3e.Unsafe.fromHtml` — its FREE
rows mean this type-checks into any slot, including `M3e.Icon`'s
`sharedIcon` kind, without needing `M3e.Unsafe.recast` on top.
-}
view : Colors -> Element accepts admittedBy msg
view colors =
    M3e.Unsafe.fromHtml
        (Svg.svg
            [ SvgAttr.viewBox "0 0 566 566"
            , SvgAttr.fill "none"
            , SvgAttr.class "tangram-mark"
            ]
            [ Svg.path [ SvgAttr.fill colors.big, SvgAttr.d "m0 0 566 566H0z" ] []
            , Svg.path [ SvgAttr.fill colors.small, SvgAttr.d "m0 0 566 566H0zM566 0v535L299 267.973z" ] []
            ]
        )
```

The `class "tangram-mark"` on the `<svg>` is the RTL-mirror hook — see Task 3.

- [ ] **Step 1: Write the generator**

```javascript
// Generates docs/public/favicon.svg as the tangram mark, baking the default
// theme's resolved primary color via @material/material-color-utilities —
// NOT `currentColor` (the previous palette-glyph favicon's mechanism), because
// the live in-session favicon-color port (`setFaviconColor`, see
// specs/2026-08-08-theme-editor-drawer-design.md) needs a real hex to start
// from and rewrite via a data: URI; `currentColor` has nothing for that port
// to read.
//
// Geometry mirrors docs/app/Logo.elm's two `d` attribute strings exactly —
// keep both in sync if the tangram geometry ever changes; Elm and this Node
// script can't literally share the constant across the language boundary.
//
// No favicon.ico, matching the existing convention this replaces (see the
// header comment this generator's predecessor, brand-images.mjs, already
// carries: a raster has no CSS context, so a fixed favicon.ico would bake in
// a color nobody chose — same reasoning applies here, doubly so now that the
// fill is a real theme-derived hex rather than currentColor).

import { writeFileSync } from "node:fs";
import { dirname, resolve } from "node:path";
import { fileURLToPath } from "node:url";
import { Hct, SchemeNeutral, MaterialDynamicColors, argbFromHex, hexFromArgb } from "@material/material-color-utilities";

const HERE = dirname(fileURLToPath(import.meta.url));
const REPO = resolve(HERE, "..", "..", "..");

// Keep in sync with docs/app/Theme.elm's `init.seed` (theme-editor-drawer
// plan, Task 7) and Shared.elm's current default seed.
const DEFAULT_SEED = "#6750A4";

const PATHS = [
  "m0 0 566 566H0z",
  "m0 0 566 566H0zM566 0v535L299 267.973z",
];

function resolvePrimaryHex(seedHex) {
  const sourceHct = Hct.fromInt(argbFromHex(seedHex));
  const scheme = new SchemeNeutral(sourceHct, /* isDark */ false, /* contrastLevel */ 0);
  return hexFromArgb(MaterialDynamicColors.primary().getArgb(scheme));
}

function buildSvg(primaryHex) {
  return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 566 566" role="img" aria-label="elm-m3e">
  <!-- GENERATED by docs/scripts/icons-gen/tangram-favicon.mjs — do not edit.
       Geometry mirrors docs/app/Logo.elm's tangram paths. -->
  <path fill="${primaryHex}" d="${PATHS[0]}"/>
  <path fill="${primaryHex}" d="${PATHS[1]}"/>
</svg>
`;
}

const primaryHex = resolvePrimaryHex(DEFAULT_SEED);
writeFileSync(resolve(REPO, "docs", "public", "favicon.svg"), buildSvg(primaryHex));
console.log(`favicon.svg regenerated — baked primary: ${primaryHex}`);
```

import { Hct, SchemeNeutral, MaterialDynamicColors, argbFromHex, hexFromArgb } from "@material/material-color-utilities";

// Mirrors docs/scripts/icons-gen/tangram-favicon.mjs's `resolvePrimaryHex` —
// keep both in sync (Node build-time generator vs. this browser-side live
// rewrite) if the derivation ever changes (e.g. tracking prefers-color-scheme

  const sourceHct = Hct.fromInt(argbFromHex(seedHex));
  const scheme = new SchemeNeutral(sourceHct, false, 0);
  return hexFromArgb(MaterialDynamicColors.primary().getArgb(scheme));
}

const TANGRAM_PATHS = [
  "m0 0 566 566H0z",
  "m0 0 566 566H0zM566 0v535L299 267.973z",
];

function tangramFaviconDataUri(primaryHex: string): string {
